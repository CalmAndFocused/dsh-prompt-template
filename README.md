# 提示词优化器

不用离开输入框，直接改好你正在写的提示词。

## 它做什么

输入框工具行右侧有一个 **提示词优化** 胶囊（`Alt+O` 同效）。写下想改进的提示词，点开它、选一个模式，改写结果**逐字流式**出现在面板里——推理过程先到，正文随后；可以随时取消。满意就点「填入输入框」，结果落回编辑器，仍可继续编辑与撤销。

## 三种模式

| 模式 | 什么时候用 | 模型会做什么 |
|---|---|---|
| 系统提示词 | 你在塑造一个助手的行为 | 重组为 Role / Profile / Skills / Rules / Workflows / Initialization |
| 用户提示词 | 你的请求含糊、信息不足 | 消除歧义，补上明显缺失的约束 |
| 迭代改进 | 已有可用的提示词，只想改一处 | 把你的需求融进现有提示词（不是执行它） |

「迭代改进」要先写清楚改什么：「输出 JSON」「不要多轮确认」「语气更正式」。

## 关键之处

这不是「把句子润色得更漂亮」。它遵循 [prompt-optimizer](https://github.com/linshenkx/prompt-optimizer) 的实现原理：

- **你的文本是证据，不是指令。** 它被作为 JSON 嵌进 user 轮，system 轮要求模型改写这段文本、而不是执行它。否则「帮我优化：不要交互」会变成「好的，我不会交互」。这条有自测守着：含引号、换行、`}]` 的输入也无法突破 JSON 信封。
- **只返回提示词本身**，没有前言、没有代码块围栏——Host 端还会再剥一次模型自作主张加上的「优化后的提示词：」和围栏。
- **`{{变量}}` 占位符逐字保留。** 模型只能调整周边表达，不能替换成具体值；面板会列出检测到的变量。
- **你不点确认，它什么都不写。** 结果只在面板里，点「填入输入框」才调用输入框自己的 `setDraft`。

## 模型

默认跑在你当前配置的默认模型上，零配置。若你在设置里填了自定义端点（OpenAI 兼容），则优先走它——这样即使 profile 里没有可用模型，优化器也能工作。

设置位置：**设置 → 通用 → 提示词优化**。可改默认模式、端点地址/模型、温度、最大输出 token、超时。API Key 存在宿主的凭据库（`DSH_PROMPT_OPTIMIZER_API_KEY`），不写进配置文件、不回显。

## Agent 工具

同一个操作同时是 agent 工具 `optimize_prompt`：当你要求助手改进一段提示词时，它调用工具而不是在回复里重写。UI 与工具共用一份 Host 实现。

## 要求

DeepSeek Harness 0.2.1-rc.2 及以上。无运行时依赖（Host 侧只用到宿主自带的 schemastery）。

## 开发

| 命令 | 作用 |
|---|---|
| `node scripts/check-templates.mjs` | 自测模板：JSON 信封不被特殊字符突破、占位符保留、原文往返一致 |
| `node scripts/make-index.mjs` | 生成插件市场索引（版本需已发布到 npm，可加 `--timestamp 0` 本地预览） |

架构：Host 半（`index.js`）提供一条 SSE 路由与一条配置路由，并注册 `optimize_prompt` 工具；Client 半（`client.js`）在 `conversation.input.right`、`conversation.input.overlay`、`settings.general.item` 各注册一个入口，共享一份按会话隔离的状态。
